# Tools

Tooling for the repository, mostly Python. The Python runs with uv, on the same Python minor version as Pyodide (see the root `pyproject.toml`).

| File                       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `validate_content.py`      | Checks everything in `content/` (see [content/README.md](../content/README.md)). CI runs it on every pull request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `content_model.py`         | The shapes of the content files, as pydantic models. Unknown fields are errors, so typos get caught.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `arithmetic.py`            | Works out an estimate item's sums ([ADR-0024](../docs/decisions/0024-estimate-questions.md)) without running them as Python: it reads the text with Python's own parser and works out only numbers, the given names, `+ - * / // % **`, brackets and six functions (`min`, `max`, `round`, `ceil`, `floor`, `abs`), in exact fractions, so 0.1 + 0.2 is 0.3. It refuses a sum that would grow past about 300 digits or is nested too deeply. `validate_content.py` uses it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `mcq_lengths.py`           | The two answer-length rules for multiple-choice items (a right answer more than 1.5 times as long as the longest wrong choice; a topic of four or more items where the right answer is the longest choice in more than half), their messages, and the reading and writing of the baseline. `validate_content.py` applies them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `mcq_length_baseline.yaml` | The older items and topics that break those rules and are tolerated until they are rewritten. Written by `validate_content.py --write-mcq-baseline`, which now only removes entries. Don't add to it by hand; deleting the line of an item you fixed is fine. Nothing from the cloud track may be on it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `parsons_orders.py`        | Lists the other ways a Parsons problem's lines could be arranged (other orders, and each decoy in place of each line), and says each one in plain words for the validator's message ([ADR-0016](../docs/decisions/0016-parsons-problems.md)). It runs nothing: `validate_content.py` runs them, to prove an item has only one working order.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `parsons_screen.py`        | The quick first pass of that check. The validator starts it in a fresh Python process, once per Parsons item, to weed out the arrangements that crash; the ones left are then run one process each. Not run by hand.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `outline_cloud_track.py`   | Reads the Cloud Solutions Architect spec and writes its track and `planned` topic outlines into `content/`. It never overwrites a topic that's being written.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `labcheck.py`              | The lab checker's local mode ([ADR-0018](../docs/decisions/0018-lab-checker-local-mode.md)): builds a lab's container from its folder in `content/` and starts it (booting systemd when the lab asks); `shell` opens a shell in it as the learner; `check` runs its checks with `docker exec` and prints the result to paste into the site. Running `start` again keeps a lab in progress (a stopped one is started again with its work); only `start --fresh` removes one. `status` lists the lab containers the tool started and `stop --all` removes them. Each check gets 30 seconds, or what its `timeout:` says (up to 300), and one that runs out of time is stopped inside the container too. `test` proves a lab's contract for authors and CI, several labs at once with `--jobs`; before a parallel run it builds the first lab of each topic on its own, so the heavy layer a topic's labs share is built once and the rest come from the cache. Before removing a container it runs the image's `/usr/local/lib/lab/teardown.sh` if there is one, so a lab can detach the loop devices behind its disks, and before a lab with disks boots, `start` lets go of the disks that dead labs left attached. Needs Docker. |
| `backup_restore_check.sh`  | Rehearses the backup's restore path ([ADR-0020](../docs/decisions/0020-automated-backups.md)) on the local database: a learner and an event in, dumped the way the nightly backup dumps, encrypted and decrypted, the database reset, the dump restored, the rows back. CI's database job runs it on every pull request; `bash tools/backup_restore_check.sh` runs it here (it resets the local database, then restores everything). Needs Docker and the local Supabase running.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `tests/`                   | Proves the validator accepts good content and catches each kind of mistake, using a tiny complete topic (`content_fixture.py`), that the outline generator writes content the validator accepts (and reads the spec's padded tables), the checker's pure parts (expectations, discovery, the result) and what its commands ask of Docker, with Docker stood in for, the estimate items' sums and rules (`test_arithmetic.py`, `test_estimate_questions.py`), and the answer-length rules with their baseline (`test_mcq_lengths.py`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `generators/`              | An archive, not tooling: the scripts that first wrote the ML topics, their review briefs and helper checks, and the parts the cloud labs were assembled from. `content/topics/` is the source of truth, so never re-run one against it. Read [its README](generators/README.md) before touching it. ruff and pytest skip the folder.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

The validator runs code through `harness/cli.py`, in a fresh Python process per program, which is exactly what the browser runs. It never imports learner code into its own process. The one place programs share a process is `parsons_screen.py`, a fresh process of its own per Parsons item, and its answer is trusted only to rule arrangements out. Labs it checks for structure only; `--labs` also runs their contract in Docker, which CI's Labs job does for every lab.

```text
python -m uv run python tools/validate_content.py      check all content
python -m uv run python tools/validate_content.py --labs   ...and prove every lab in Docker
python -m uv run python tools/validate_content.py --write-mcq-baseline   drop fixed entries from the answer-length baseline
python -m uv run python tools/outline_cloud_track.py   refresh the cloud track's outlines from its spec
python -m uv run pytest                                run the harness and tool tests

python -m uv run python tools/labcheck.py list                                  every lab
python -m uv run python tools/labcheck.py start csa.linux.shell build-log-report  build and start it, or carry on with it
python -m uv run python tools/labcheck.py start --fresh csa.linux.shell build-log-report  begin again: removes the work
python -m uv run python tools/labcheck.py shell csa.linux.shell build-log-report  open a shell in it, as the learner
python -m uv run python tools/labcheck.py check csa.linux.shell build-log-report  run the checks, print the result
python -m uv run python tools/labcheck.py stop  csa.linux.shell build-log-report  remove the container and the work in it
python -m uv run python tools/labcheck.py status                                the labs this tool started
python -m uv run python tools/labcheck.py stop  --all                           remove them all
python -m uv run python tools/labcheck.py test  --all --jobs 4                  prove every lab's contract, four at a time
```
