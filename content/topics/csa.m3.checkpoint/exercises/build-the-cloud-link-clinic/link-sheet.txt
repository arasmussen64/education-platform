How the cloud chooses between your two paths
  The cloud's router treats the circuit and the VPN alike. For a prefix it
  hears over both, it prefers the shorter AS path, modelled on Azure's VPN
  gateway between two connections: "Azure VPN Gateway honors autonomous
  system (AS) path prepending to help make routing decisions when BGP is
  enabled. A shorter AS path is preferred in BGP path selection."
  (https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-vpn-faq,
  read 2026-11-12). Azure's answer for choosing between connections is
  prepending ("you need to use AS path prepending"); this lab's router,
  like most BGP routers, also compares the lower MED when the AS paths are
  the same length. Its AS number, 65515, is the one Azure gives every VPN
  gateway by default, and the VPN's inside addresses come from the range
  Azure's gateways take for BGP over APIPA addresses, 169.254.21.0 to
  169.254.22.255. It uses one path at a time, never both, and honours no
  BGP communities. When nothing tells the two paths apart, it takes the
  one from the lower neighbour address, which is the VPN's.

  (Real Azure makes an ExpressRoute circuit the primary link for the same
  prefix by itself, and its guide asks the router on your side to set "a
  higher local preference for the routes received via ExpressRoute". This
  cloud doesn't prefer the circuit by itself, so which way its traffic
  comes back is yours to decide, as it is between two VPN connections.)
