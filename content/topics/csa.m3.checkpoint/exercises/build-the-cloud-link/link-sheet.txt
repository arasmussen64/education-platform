How the cloud chooses between your two paths
  The cloud's router treats the circuit and the VPN alike. For a prefix it
  hears over both, it prefers the shorter AS path, then the lower MED,
  modelled on AWS's virtual private gateway between two VPN connections:
  "the AS PATH is compared and the prefix with the shortest AS PATH is
  preferred", then "the path with the lowest MED value is preferred"
  (https://docs.aws.amazon.com/vpn/latest/s2svpn/vpn-route-priority.html,
  read 2026-11-12). It uses one path at a time, never both: "ECMP is not
  supported for Site-to-Site VPN connections on a virtual private gateway".
  It honours no BGP communities. When nothing tells the two paths apart, it
  takes the one from the lower neighbour address, which is the VPN's.

  (Real clouds also prefer a circuit to a VPN for the same prefix by
  themselves: AWS puts Direct Connect's routes before a VPN's, and Azure
  makes ExpressRoute the primary link. This one doesn't, so which way the
  cloud's traffic comes back is yours to decide, as it is between two VPN
  connections or two circuits.)
