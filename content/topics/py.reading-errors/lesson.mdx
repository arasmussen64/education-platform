<Intro>

Every programmer's screen fills with red text several times an hour. The difference between a beginner and an experienced programmer isn't fewer errors; it's that the experienced one *reads* the message instead of guessing. An error message is Python telling you exactly where it got stuck and why.

The reading below is Python's own guide to errors. Read the first two sections, **Syntax Errors** and **Exceptions**, and skip the rest for now (handling errors with `try` is Module 6). Watch for:

- **The two kinds of error.** A *syntax error* is found before the program runs at all: Python can't make sense of the text. An *exception* happens while the program is running, when a line turns out to be impossible.
- **The shape of a traceback**: a `File ... line N` part saying where, the line of code itself, and a last line saying what. The last line is the one to read first.
- **The names of common exceptions**, like `NameError`, `TypeError` and `ValueError`. The recap below says what each one usually means in the programs you've written so far.

Then open the Python Tutor link and press **Next >** until the error appears. Notice that the first two lines ran fine: errors happen at a line, not to a whole program.

<Recap>

**How to read a traceback.** Read the **last line first**: it names the error and says what went wrong. Then find the **`line N`** above it and go to that line in your code. The problem is on that line, or occasionally just before it.

**Five errors you'll meet all the time:**

| Error | What it usually means |
|---|---|
| `SyntaxError` | Python can't read the line: a missing `)` or `"`, a missing `:` at the end of an `if`, or `=` where `==` was meant in an `if` line. Found before anything runs, so nothing is printed. |
| `IndentationError` | A line is indented when it shouldn't be, or not indented when it should (every line under `if ...:` needs to be). |
| `NameError: name 'x' is not defined` | You used a name that was never given a value: a misspelling, or a line that runs before the one that defines it. |
| `TypeError` | Two values of the wrong types met: text and a number in `+`, or something that isn't a number in maths. With `input()`, it almost always means a missing `int()` or `float()`. |
| `ValueError` | The type is right but the value doesn't fit: `int("twenty")`, or `int("3.5")`. |

**One message that breaks the pattern.** `ValueError: Unknown format code 'f' for object of type 'str'` is a missing conversion too, even though it isn't a `TypeError`. It means text reached a `:.2f`, which can only show numbers; `str` in the message is Python's name for text. The line it names is the f-string, but the mistake is usually earlier: look for an `input()` that never went through `float()`. Nothing stopped the program sooner because text times a whole number isn't an error: `3 * "1.25"` quietly repeats the text.

**The fixing routine:**

1. Read the last line of the traceback. Name the error.
2. Go to the line number it gives. Read that line slowly.
3. Check the names (spelled the same everywhere? given a value before this line?) and the types (text or number? converted?).
4. Change **one** thing.
5. Run again and read the new message. A different error is progress.

Fixing one error often reveals the next one, because Python stops at the first problem it meets. That's normal: keep going, one at a time.

</Recap>
