<Intro>

A model is only as good as the number you can honestly report for it, and this topic is how to earn that number. Three **splits** keep fitting, choosing and reporting apart; the **confusion matrix** turns a classifier's answers into four counts and the metrics that come from them, because accuracy alone can hide a useless model; the last topic's standard error puts an interval on an accuracy; and a **paired bootstrap** says whether one model really beats another on the same examples. The worked example judges two classifiers on 200 held-out examples with every tool in the module.

The main resource is **Google's Machine Learning Crash Course, the classification pages** on thresholds, the confusion matrix, and accuracy, recall and precision; about 30 minutes of reading with small interactive exercises. Wikipedia's _Precision and recall_ has the definitions and the standard picture. Watch for:

- **Four counts** behind every classification metric.
- **Which mistake costs more** decides which metric to watch.
- **The threshold is a choice**, made on validation data.

</Intro>

<Recap>

- **Three splits.** **Train** fits the weights. **Validation** chooses what training can't: the threshold, the learning rate, when to stop, which model to keep. **Test** is touched once, to report. Using the test set for any choice is **leakage**: the number becomes the best of many tries on those examples and stops estimating performance on new data. In the worked example, the threshold chosen on validation data gave a test accuracy of 0.85; the one chosen on the test set itself gave 0.86, a number that flatters.
- **The confusion matrix** splits a classifier's answers into **true positives** (flagged, and right), **false positives** (flagged, but wrong), **false negatives** (missed) and **true negatives** (correctly left alone). Every metric is built from those four counts.
- **Accuracy** is `(tp + tn) / n`, and it misleads on a rare class: the worked example's data is 30 percent positive, so "always no" scores 0.63 without learning anything. **Precision** `tp / (tp + fp)` asks "of the ones flagged, how many were right?"; **recall** `tp / (tp + fn)` asks "of the real ones, how many were found?"; **F1** is their harmonic mean, `2pr / (p + r)`, low if either is low. Which mistake costs more decides which to watch: a screening test wants recall, a spam filter wants precision.
- **Model A against model B:** A scores 0.83  0.744 0.824 0.782 on accuracy, precision, recall and F1, B scores 0.74  0.631 0.716 0.671.
- **An interval on an accuracy.** An accuracy is the mean of `n` zeros and ones, so its standard error is `sqrt(p(1 - p) / n)`: for A, 0.027, and the 95 percent interval is 0.778 0.882. On 200 examples, two models two points apart are about one standard error apart: not yet distinguishable.
- **Comparing two models on the same examples:** don't compare two intervals; compare the models **paired**. For each example take A's correctness minus B's, bootstrap the mean of those differences, and read the interval. In the worked example the mean difference is 0.09 with an interval of 0.015 0.165, which stays above zero, so even with the sampling noise A is better on this test set. Pairing removes the noise the two models share (the hard examples are hard for both).
- **When a test set is too small to tell,** the interval says so: the fix is more test data, not a different metric.
- **In machine learning:** every leaderboard number is a sample mean with a standard error nobody printed; "we tuned on the test set" is the commonest way a published result fails to replicate; and a model's threshold is a product decision about which mistake is dearer, set on validation data and reported on test data.

</Recap>
