<Intro>

Linux was built for many people sharing one machine, and that is still how a server works: the web app, the database, the backup job and you are all different **users**, and every file says who may do what with it. Get this right and a broken app can only damage its own corner. Get it wrong and a typo in a script deletes the database.

**Reading `ls -l`.** Each line looks like this:

```
-rwxr-x--- 1 app  app   120 Nov  9 09:00 deploy.sh
drwxr-x--- 2 app  app  4096 Nov  9 09:00 secrets
```

The first ten characters are the **mode**. The first one is the type: `-` for an ordinary file, `d` for a directory, `l` for a link. Then come three groups of three: what the **owner** may do, what members of the file's **group** may do, and what **others** may do. In each group, `r` is read, `w` is write, `x` is execute, and `-` means "not allowed". So `deploy.sh` can be read, changed and run by its owner (`app`), read and run by members of the `app` group, and not touched by anyone else. After the mode come the number of links, the owner, the group, the size in bytes, the date, and the name.

**What the letters mean.** On a file, `r` lets you read it, `w` change it, `x` run it as a program. On a directory they mean something slightly different: `r` lets you list the names inside, `w` lets you create and delete entries, and `x` lets you *enter* it and reach the files inside. A directory without `x` is a locked room even if you know what's in it, which is why directories almost always have `x` wherever they have `r`.

**Octal.** Each group of three is also a number: `r` is 4, `w` is 2, `x` is 1, added up. `rwx` is 7, `r-x` is 5, `r--` is 4, `---` is 0. So `-rwxr-x---` is **750**. You'll see a few numbers everywhere: `644` for ordinary files (owner writes, everyone reads), `755` for programs and directories, `600` for secrets (only the owner, and no running), `700` for private directories such as `~/.ssh`.

**Changing things.** `chmod 750 deploy.sh` sets the mode outright; the symbolic form changes one piece: `chmod u+x deploy.sh` (owner may execute), `chmod g-w notes.txt` (group may not write), `chmod o= secrets` (others get nothing). `chown app:app /srv/app` sets the owner and group, and `-R` does the whole tree. Only the file's owner or root may change these. New files aren't created with 666 or 777 even though that's where the kernel starts: the **umask** takes bits away. With the usual `umask 022`, new files come out 644 and new directories 755; with `umask 077`, 600 and 700.

**Users and groups.** `/etc/passwd` has one line per user: `name:x:uid:gid:comment:home:shell`. root has uid 0 and may do anything. Service users like `www-data` have no password and `/usr/sbin/nologin` as a shell, so nobody can log in as them: they exist only to own files and run one program. `id` shows who you are and which groups you're in. Groups let several users share access: give the `deploy` group write access to `/srv/app`, and `usermod -aG deploy ada` adds Ada to it, taking effect the next time she logs in. The `-a` matters: without it, `usermod -G` *replaces* her groups.

**Root and sudo.** Logging in as root means every command you type has unlimited power and no name attached. `sudo command` runs one command as root, asks for *your* password, and writes a line to the log saying who ran what. Who may use it is in `/etc/sudoers`, edited with `visudo` (which checks the syntax before saving, because a broken sudoers locks everyone out). `%sudo ALL=(ALL:ALL) ALL` lets the `sudo` group run anything; a line like `%deploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart app` lets one group run one command, which is the shape you want: the least power that does the job. On servers, `PermitRootLogin no` in the SSH config closes the front door for root entirely.

**SSH keys.** Passwords over the network can be guessed; keys can't. `ssh-keygen -t ed25519` creates a pair of files in `~/.ssh`: `id_ed25519`, the **private key**, and `id_ed25519.pub`, the **public key**. The private key never leaves your machine; give it a passphrase and let `ssh-agent` remember it. The public key is just text, and you append it to `~/.ssh/authorized_keys` in your account on the server (`ssh-copy-id user@host` does this). From then on the server challenges you to prove you hold the private key, without ever seeing it. `sshd` is strict about the files: `~/.ssh` must be `700` and `authorized_keys` and the private key `600`, or it silently ignores them, because a key another user could read or edit is already compromised. `~/.ssh/config` saves typing: a `Host web` block with `HostName`, `User` and `IdentityFile` lets you type `ssh web`. Once keys work on a server, turn password login off.

<Recap>

- **`ls -l`:** type (`-` file, `d` directory, `l` link), then `rwx` for the owner, the group and others; then links, owner, group, size, date, name.
- **On a directory:** `r` lists names, `w` creates and deletes entries, `x` lets you enter it. No `x`, no access to what's inside.
- **Octal:** `r`=4, `w`=2, `x`=1 per group. `644` files, `755` programs and directories, `600` secrets, `700` private directories. `-rwxr-x---` is `750`.
- **`chmod 750 f`**, `chmod u+x f`, `chmod g-w f`, `chmod o= f`; **`chown app:app f`**, `-R` for a tree. Owner or root only.
- **`umask`:** new files start from 666, directories from 777, minus the mask: `022` gives `644`/`755`, `077` gives `600`/`700`.
- **Users:** `/etc/passwd` is `name:x:uid:gid:comment:home:shell`; root is uid 0; service users have `nologin`; `id` shows your groups; `usermod -aG group user` (keep the `-a`), effective at next login.
- **sudo** runs one command as root with your own password and logs it; `visudo` edits `/etc/sudoers`; `%group`, and `NOPASSWD:` for one specific command, is least privilege. `PermitRootLogin no`.
- **SSH keys:** `ssh-keygen -t ed25519` makes `id_ed25519` (private, stays, `600`, passphrase + agent) and `id_ed25519.pub` (public, appended to the server's `~/.ssh/authorized_keys`, via `ssh-copy-id`). `~/.ssh` is `700`. `~/.ssh/config` holds `Host` blocks. Then turn password login off.

</Recap>
