<Intro>

You've been *calling* functions since your first line of code: `print`, `input`, `int`, `len`, `range`. Each one is a named piece of work that someone else wrote. This module is about writing your own. In this clip, David tries to call a function called `hello` that doesn't exist yet, and then builds it. Watch for:

- **`def`**, short for *define*: the keyword, a name, parentheses, a colon, and an indented body, exactly like the body of a loop. Defining a function runs nothing. It stores the recipe.
- **Calling** the function: its name with parentheses, `hello()`. That's when the body runs.
- **A parameter** (David calls his `to`): a name in the parentheses of the `def` that stands for whatever value the caller passes in. The value you pass is the **argument**.
- **A default value**, `to="world"`: what the parameter gets when the caller leaves it out.
- **`main()`**: David moves the program's steps into a function called `main`, defined at the top, and calls it once at the bottom. Notice *why*: Python reads the file top to bottom, and by the time the last line calls `main()`, every `def` has been read.
- Near the end, a variable made inside `main` isn't known inside `hello`. David fixes it by passing the value in. That's **scope**, and it gets its own topic two steps from now.

Then read the tutorial's short **Defining Functions** section, up to the part about `return` (the next topic).

<Recap>

```python
def greet(name, greeting="Hello"):     # define: name, parameters, colon
    print(f"{greeting}, {name}!")      # the body, indented


def main():
    greet("Ada")                       # call: Hello, Ada!
    greet("Bob", "Hi")                 # call: Hi, Bob!


main()                                 # the one call that starts everything
```

- **Define, then call.** `def` stores the body under a name and runs nothing. The body runs each time the function is *called*: the name followed by parentheses. `greet` alone is just the name; `greet("Ada")` does the work.
- **Parameters and arguments.** `name` and `greeting` are parameters: placeholders in the definition. `"Ada"` is an argument: the value passed in a call. Arguments fill parameters **in order**, so `greet("Bob", "Hi")` makes `name` `"Bob"` and `greeting` `"Hi"`. Too few or too many arguments is a `TypeError`.
- **Default values.** `greeting="Hello"` is used when the caller gives no second argument. Parameters with defaults go after the ones without.
- **The `main()` pattern.** Put the program's steps in `main()`, define it and every other function above, and call `main()` once at the very bottom. Python reads a file top to bottom: a call only works once the `def` above it has been read, and with this pattern every `def` has been.
- **Order of definitions doesn't matter;** order of definition and call does. `main` can call a function defined below it, because nothing runs until `main()` on the last line.
- **One job per function,** named with a verb for what it does: `greet`, `print_banner`, `ask_age`. Names like `thing` or `function1` hide what the code is for.

</Recap>
