<Intro>

In the last topic, David asked three separate questions with three separate `if` statements. This clip is about asking them better. Watch for:

- **`elif`**, short for "else if": a question that's only asked when the one above it was `False`. Once a condition is `True`, its lines run and the rest of the chain is skipped.
- **`else`**: no question at all, just "otherwise". It runs when every condition above it was `False`.
- **Why the order matters.** David's three questions can't all be true at once, so he keeps cutting them down: three `if`s, then `if`/`elif`/`elif`, then `if`/`elif`/`else`. Fewer questions means fewer chances to make a mistake.
- **The shape of a block.** Every `if`, `elif` and `else` line ends with a colon, and the lines that belong to it are indented underneath. The indentation isn't decoration: it's how Python knows what belongs where.

</Intro>

<Recap>

- **`if condition:`** runs the indented lines under it only when the condition is `True`. Otherwise Python skips them.
- **`else:`** has no condition. Its lines run when the `if` (and any `elif`) above it didn't.
- **`elif condition:`** adds another question, asked only if everything above it was `False`. A chain can have as many `elif`s as you like, and `else` at the end is optional.
- **The first `True` condition wins.** Python runs that branch and skips the rest, even if later conditions would also be `True`. So put the strictest test first: `score >= 90` before `score >= 60`.
- **Colons and indentation.** The `if` line ends with `:`, and every line that belongs to it is indented by the same amount (four spaces is the convention). A line that isn't indented runs every time, whatever the condition was.
- Two separate `if` statements are two separate questions, and both can run. `if`/`elif` is one question with several answers, and only one branch runs.
- Later, `match` is another way to choose between many values. You can live without it for a long time.

</Recap>
