<Intro>

A model's loss doesn't depend on one knob; it depends on thousands. The last topic's derivatives were slopes along one axis. This topic puts them together: the slope along each axis with the others held still is a **partial derivative**, the vector of all of them is the **gradient**, and the gradient is the direction in which the loss rises fastest. Training steps the other way. Every claim here is checked in code, one coordinate at a time.

**Several inputs, one output.** Every function in Derivatives took one number and gave one number back. The functions that matter in machine learning take several numbers and give back one: a loss takes every weight of the model and returns how wrong the model is. Start with two inputs, because two can be pictured. Call them `x` and `y`, and think of them as a position on a map: `x` is how far east you are and `y` is how far north. The output is the height of the ground there. Here is a made-up function to practise on, `f(x, y) = x² + x y + 4y`:

```python
import numpy as np


def f(p):
    x, y = p
    return x**2 + x * y + 4 * y


p = np.array([2.0, 4.0])
print(f(p))
```

```
28.0
```

The inputs travel together as one array, `p`, called a **point**, and the first line of `f` unpacks it into `x` and `y`. At the point `(2, 4)` the function's value is `4 + 8 + 16 = 28`. Nothing about this needs exactly two inputs: a point with a thousand entries works the same way, it just can't be drawn.

**A partial derivative: move one input, freeze the rest.** With one input, "how fast does the output change?" had one answer, the derivative. With two inputs the answer depends on which input you move. So ask the question one input at a time.

Stand at `(2, 4)` and move only `x`. While you do, `y` stays at 4, so it is no longer a variable: it is the number 4. Put 4 in for `y` and the function becomes `x² + 4x + 16`, an ordinary function of one variable. The rules from Derivatives give its derivative, `2x + 4`, which is 8 at `x = 2`. That 8 is the **partial derivative** of `f` with respect to `x` at `(2, 4)`: the slope you feel walking due east.

You don't have to put the number in first. Leave `y` as a letter, treat it as a constant, and differentiate each term with respect to `x`:

- `x²` gives `2x`, by the power rule.
- `x y` is a constant, `y`, times `x`. The derivative of a constant times `x` is the constant, so this term gives `y`.
- `4y` has no `x` in it at all. It is a constant, and the derivative of a constant is 0.

So the partial derivative with respect to `x` is `2x + y`, written `∂f/∂x = 2x + y`. The curly `∂` is read "partial"; it stands where the `d` of an ordinary derivative would, and only says that `f` has other inputs and they were held still. At `(2, 4)` it is `4 + 4 = 8`, as before.

Now the other way: move `y` and freeze `x`. `x²` has no `y` in it, so it gives 0. `x y` is the constant `x` times `y`, so it gives `x`. `4y` gives 4. So `∂f/∂y = x + 4`, which is 6 at `(2, 4)`: the slope you feel walking due north.

The same routine works for any number of inputs. For `g(a, b, c) = a b + c²`, the partial with respect to `a` is `b`, with respect to `b` it is `a`, and with respect to `c` it is `2c`.

Two slips are common. One is to differentiate a frozen variable as well, so that the `x` partial of `4y` comes out as 4 when it should be 0. The other is to throw away a frozen variable that multiplies the moving one: the `x` partial of `x y` is `y`, not 1 and not 0. A frozen variable that **multiplies** stays as a multiplier; a term the moving variable isn't in **disappears**.

**The gradient: all the partials, in one vector.** A function of two inputs has two partial derivatives at every point, and one of a thousand inputs has a thousand. Put them in a vector, in the same order as the inputs, and you have the **gradient**, written `∇f` and read "grad f". For this function `∇f = [2x + y, x + 4]`:

```python
def gradient(p):
    x, y = p
    return np.array([2 * x + y, x + 4])


print(gradient(p))
print(gradient(np.array([0.0, 0.0])))
print(gradient(np.array([-3.0, 1.0])))
```

```
[8. 6.]
[0. 4.]
[-5.  1.]
```

Two things to notice. The gradient takes a point and returns a vector of the same size, and it is a different vector at each point, because the ground slopes differently in different places. And it says nothing about the height itself: `[8, 6]` at `(2, 4)` does not tell you that `f` is 28 there, only how `f` changes as you leave.

**Checking a gradient with numbers, one coordinate at a time.** A partial derivative worked out by rule is a claim, and Derivatives gave the tool for testing claims about slopes: the central difference, `(f(x + h) - f(x - h)) / (2 * h)` with a small `h` (a **finite difference**: a slope measured between two nearby values). It carries over with one change. To estimate the partial for one coordinate, nudge **that coordinate only**. The nudge is itself an array, zero everywhere except for `h` in the slot being tested:

```python
h = 1e-6
step = np.zeros(2)
step[0] = h
print(round((f(p + step) - f(p - step)) / (2 * h), 6))

step = np.zeros(2)
step[1] = h
print(round((f(p + step) - f(p - step)) / (2 * h), 6))
```

```
8.0
6.0
```

`np.zeros(2)` is `[0, 0]`. With `h` put in slot 0, `p + step` is the point a hair to the east and `p - step` a hair to the west, with `y` untouched, so the central difference between them is the `x` partial. The second half starts again from a fresh `[0, 0]` and puts `h` in slot 1. Both estimates agree with the rule. For a point with more entries the same thing is done in a loop over the slots, filling in one entry of the answer on each pass, and the result is called a **numeric gradient**.

The classic mistake is to nudge everything at once. Adding a plain number to an array adds it to every entry, so `p + h` moves east and north together:

```python
print(round((f(p + h) - f(p - h)) / (2 * h), 6))
```

```
14.0
```

That is 8 + 6, the sum of the two partials. It is not a partial derivative of anything, and a loop that makes this mistake fills every slot of its answer with the same wrong number.

To compare a gradient by rule with a numeric one, subtract them, take absolute values, and look at the **largest** gap. The largest, because one wrong entry is a wrong gradient, and an average would water it down. Suppose someone forgot the `y` that the `x y` term contributes and wrote the `x` partial as `2x`:

```python
numeric = np.array([8.0, 6.0])
wrong = np.array([2 * p[0], p[0] + 4])
print(np.abs(wrong - numeric))
print(np.abs(wrong - numeric).max())
```

```
[4. 0.]
4.0
```

A correct formula and a central difference with `h = 1e-6` agree to within about a billionth here, so this module's test is a largest gap below `1e-6`, a millionth. A gap of 4 is a mistake in the formula. One point is not enough, though: a wrong formula can happen to be right at a single point (this one is right wherever `y` is 0), so a careful check tries several points and reports the largest gap over all of them. This is called a **gradient check**, and it is what people run before trusting a gradient they wrote by hand.

**The rate of change in any direction.** East and north are only two of the ways you could walk. What is the slope if you set off north-east, or in any other direction?

Describe a direction by a **unit vector** `u`, a vector of length 1, as in Vectors: east is `[1, 0]`, north is `[0, 1]`. One step of length 1 along `u = [u1, u2]` moves you `u1` to the east and `u2` to the north. The eastward part changes `f` at the rate `∂f/∂x` and the northward part at the rate `∂f/∂y`, and for a small step the two changes simply add. So the rate of change along `u` is

`∂f/∂x * u1 + ∂f/∂y * u2`

which is exactly the dot product of the gradient with `u`: `∇f · u`, or `g @ u` in code. This rate is called the **directional derivative**. It can be tested like any other slope. North-east as a unit vector is `[1, 1]` divided by its length, about `[0.707, 0.707]`, so the rate should be `8 * 0.707 + 6 * 0.707`, which is 9.899. Walk 0.001 that way from `(2, 4)` and `f` rises by 0.0099005: a rate of 9.9, as predicted.

Here is the rate from `(2, 4)`, where the gradient is `[8, 6]`, in six directions:

| Direction                | Unit vector `u`  | Rate, `[8, 6] · u` |
| ------------------------ | ---------------- | ------------------ |
| east                     | `[1, 0]`         | 8                  |
| north                    | `[0, 1]`         | 6                  |
| north-east               | `[0.707, 0.707]` | 9.899              |
| the gradient's own       | `[0.8, 0.6]`     | 10                 |
| at right angles to it    | `[0.6, -0.8]`    | 0                  |
| opposite to the gradient | `[-0.8, -0.6]`   | -10                |

With `u = [1, 0]` the dot product picks out the first partial, and with `[0, 1]` the second: the partial derivatives are the directional derivatives along the axes.

**The direction must have length 1.** A rate is "change in `f` for each unit of distance walked", so the arrow that names the direction mustn't bring a length of its own. Use `[1, 1]` for north-east without scaling it and the dot product is 14, larger than the rate in any real direction; use `[2, 2]` and it is 28. Same direction, different answers, both wrong. Divide the arrow by its length first, `d / np.linalg.norm(d)`, or divide the dot product by that length afterwards, which comes to the same thing.

**Why the gradient points uphill fastest, and what its length means.** The table's largest rate is along the gradient's own direction. That is not luck. Vectors showed that a dot product is the two lengths times the cosine of the angle between the vectors. Here `u` has length 1, so

`∇f · u = (length of ∇f) * cos(angle between ∇f and u)`

The length of the gradient is fixed at a given point; only the angle changes as you turn. A cosine is largest, 1, when the angle is zero: when `u` points the same way as the gradient. So:

- **The gradient's direction is the direction of steepest ascent,** the way `f` rises fastest. As a unit vector it is the gradient divided by its own length.
- **The gradient's length is the rate in that direction,** the steepest slope there is at that point. A long gradient means steep ground; a short one means nearly level ground.
- **Straight against the gradient** the cosine is -1 and the rate is minus the length: the steepest way down. This is the direction training steps in.
- **At right angles to the gradient** the cosine is 0, and so is the rate.

```python
g = gradient(p)
print(np.linalg.norm(g))
print(g / np.linalg.norm(g))
```

```
10.0
[0.8 0.6]
```

From `(2, 4)` the fastest way up is `[0.8, 0.6]`, mostly east and somewhat north, and going that way `f` rises 10 for each unit walked. Going north-east instead gets 9.899: close, but nothing beats the gradient's own direction. And a small step the other way, `p - 0.01 * g`, lands on `(1.92, 3.94)`, where `f` is 27.0112. That step had length 0.1, and at a rate of -10 it should have lowered `f` by about 1; it lowered it by 0.9888.

**Contour lines.** A walking map shows height with **contour lines**: each line joins places of equal height. A function of two inputs has them too. The **contour** through a point is the curve of all the points where `f` has the same value. For this function the contour through `(2, 4)` is where `f` is 28, and it also passes through `(0, 7)` and `(4, 1.5)`: put either into the formula and you get 28.

Walk along a contour and, by definition, `f` doesn't change: the rate of change in that direction is 0. The rate in a direction `u` is `∇f · u`, and Vectors showed that a dot product of 0 means the two vectors are perpendicular. So **the gradient is perpendicular to the contour through its point.** That is the fifth row of the table: `[0.6, -0.8]` is at right angles to `[8, 6]`, the rate along it is 0, and it is the way the contour runs at `(2, 4)`. Step 0.01 along it and `f` goes from 28 to 27.999988, hardly a change at all (not exactly none, because the contour is a curve and the step was straight).

Two things follow. If you know the gradient at a point, you know which way the contour runs there: across it. And descent, which steps against the gradient, always crosses the contours at right angles, heading straight for lower ones, never sliding along one.

**Where the gradient is zero.** If every partial derivative is zero, then `∇f · u` is zero for every direction `u`: the ground is level whichever way you face. One zero entry is not enough. At `(0, 0)` this function's gradient is `[0, 4]`, level going east and climbing going north. There are three kinds of level place:

- the bottom of a valley, a minimum, where every direction leads up;
- the top of a hill, a maximum, where every direction leads down;
- a **saddle**, which is a bottom along one direction and a top along another. `x² - y²` has one at `(0, 0)`: its gradient, `[2x, -2y]`, is `[0, 0]` there, yet moving along `x` raises it and moving along `y` lowers it, like the middle of a horse's saddle.

A zero gradient says the surface is flat, not that the function is zero or that the inputs are zero. And descent's step is a multiple of the gradient, so wherever the gradient is zero the step is zero and descent stops moving, whichever of the three it has found.

**In machine learning** the map is the loss, the inputs are the model's weights, and training repeats one move: work out the gradient of the loss with respect to every weight, then step against it. The topics after this one build the two halves, the stepping (descent in many dimensions) and working out a big gradient efficiently (the chain rule and backpropagation). The numeric gradient is far too slow to train with, since it needs two runs of the function for every weight, but it is the standard test that a faster hand-written gradient is right.

<Recap>

- **Several inputs, one output.** `f(x, y) = x² + 3y²` is a bowl over the plane, steeper in `y`. In code a point is an array `p = np.array([x, y])` and `f(p)` returns one number; a loss is this with thousands of entries in `p`.
- **A partial derivative** is the derivative with respect to one variable while the others are held fixed: `∂f/∂x = 2x` (treat `y` as a constant), `∂f/∂y = 6y`. The curly `∂` just says "one variable of several".
- **The gradient** stacks the partials into a vector, written `∇f` (read "grad f"): `∇f = [2x, 6y]`, so `[2, 6]` at `(1, 1)`. Its **direction** is the way `f` rises fastest from that point; its **length** (6.325 there) is how fast `f` rises per unit step in that direction.
- **Checking it numerically**, one coordinate at a time: nudge entry `i` by `h` up and down, leaving the others alone, and take the central difference (a **finite difference**: the slope between two nearby values, as in the last topic). In code: a `step` array of zeros with `h` in slot `i`, `(f(p + step) - f(p - step)) / (2 * h)`. Nudging every entry at once gives the sum of the partials, which is wrong.
- **The directional derivative:** the rate of change along a **unit** direction `u` is `∇f · u`. Along the gradient's own direction it's the gradient's length; along a direction perpendicular to the gradient it's zero. Divide a direction by its length before using it, or the answer scales with the arrow you drew.
- **Contours.** A contour line (a height line on a map) is a curve along which `f` doesn't change. Along it the rate is zero, so the gradient is **perpendicular** to the contour through the point. Descent, stepping against the gradient, crosses contours at right angles towards lower ones.
- **Where the gradient is zero,** the surface is flat: the bottom of a bowl, the top of a hill, or a saddle (a point that is the bottom one way and the top the other way). Descent stops moving there, which is what it's looking for.
- **In machine learning:** training's backward pass, which the chain rule topic builds, computes exactly this, the gradient of the loss with respect to every weight, and every optimizer in the next topics is a rule for stepping against it. A numeric gradient check is the standard way to prove a hand-written one is right before training on it.
