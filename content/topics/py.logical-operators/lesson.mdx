<Intro>

So far each `if` has asked one question. This clip is about asking two at once. Watch for:

- **`or`**: David rewrites the comparison program to ask "is `x` less than `y` **or** greater than `y`?" Either being `True` is enough.
- **`and`**: in the grade program, a score is an A if it's at least 90 **and** at most 100. Both have to be `True`.
- **Chaining**: Python lets you write `90 <= score <= 100` as one comparison, which reads like maths.
- **Trimming the chain.** Once the first branch has caught the 90s, the next branch doesn't need to check "under 90" again: an `elif` is only reached when everything above it was `False`. David uses that to simplify the grade program.
- **Near the end**, a student asks what happens if the branches aren't mutually exclusive, that is, if more than one condition could be `True` at once. The answer is the "first `True` wins" rule from the last topic.

One thing the clip doesn't show, which trips up almost everyone: `day == "Sat" or "Sun"` does *not* check for both days. The recap explains why.

</Intro>

<Recap>

- **`and`** is `True` only when both sides are `True`: `age >= 18 and age < 65`.
- **`or`** is `True` when either side is `True` (or both): `day == "Sat" or day == "Sun"`.
- **`not`** flips an answer: `not raining` is `True` when `raining` is `False`.
- **Each side of `and` and `or` is a complete question.** `x == 1 or x == 2` asks two questions. `x == 1 or 2` asks one question and then just says `2`, and Python treats a number other than zero (or any non-empty text) as `True`. So `x == 1 or 2` is **always** `True`, with no error to warn you. Write the comparison on both sides, every time.
- **Between two numbers**: `low <= x and x <= high`, or the chained form `low <= x <= high`, which means the same.
- In an `if` / `elif` chain, each `elif` is only reached when everything above it was `False`, so it doesn't need to repeat those conditions. `elif score >= 80` is enough once `score >= 90` has been handled.
- Comparisons are checked before `and` and `or`, so `a > 1 and b > 1` needs no brackets. Brackets never hurt when they make a condition clearer.

</Recap>
