<Intro>

Every value in Python has a **type**: a kind of value. In this part of the lecture, watch for:

- **What an `int` is**: a whole number, with no decimal point.
- **The calculator bug**: David types `1` and `2`, and his program prints `12`. Why would that happen?
- **The fix**: how `int(...)` turns text that looks like a number into a real number.

The video uses a few things you haven't learned yet. Lines like `x = 1` give a value a name (that's variables, the next topic), and `input()` asks the user to type something (topic 5). Don't worry about them; watch what happens to the values. Partway through, David also shows Python's interactive mode, the `>>>` prompt. You don't need it here: the **Run** button does the same job.

<Recap>

- Every value has a **type**. Three you'll use all the time:
  - **`str`** (a string): text, written in quotes, like `"hello"` or `"42"`;
  - **`int`** (an integer): a whole number, like `42`, `0` or `-7`;
  - **`float`**: a number with a decimal point, like `3.5` or `2.0`.
- **Quotes decide** whether it's text: `"42"` is a `str`, `42` is an `int`. **The decimal point decides** int or float: `2` is an `int`, `2.0` is a `float`.
- `print` doesn't show quotes, so `print(42)` and `print("42")` look exactly the same. To find out a value's type, ask: `print(type("42"))` shows `<class 'str'>`. Just read the name in quotes: `str`.
- **`+` depends on the types.** Numbers add: `2 + 3` is `5`. Text joins: `"2" + "3"` is `"23"`. Text plus a number is an error, a `TypeError`.
- Some type bugs crash with a `TypeError`. Others, like the calculator printing `12`, run without any error and quietly print the wrong thing. That's why you check the output, not just whether it ran.
- `int(...)` turns text like `"5"` into the number `5`, and `float(...)` does the same for decimals; you'll use them with `input()` in a later topic. `str(...)` goes the other way: `str(30)` is the text `"30"`, ready to join to other text with `+`.

</Recap>
