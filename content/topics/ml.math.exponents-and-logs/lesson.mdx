<Intro>

A power is repeated multiplication, and a logarithm is the question "how many times?" asked backwards. Machine learning is full of both: data that doubles, errors that halve, and probabilities so small that only their logarithms fit in a computer.

**A power is repeated multiplication.** `3 ** 4` means four 3s multiplied together: `3 * 3 * 3 * 3`, which is 81. The number being multiplied, 3, is the **base**. The count of how many times, 4, is the **exponent**, and the whole thing is read "3 to the power 4". The mistake to avoid is reading it as `3 * 4`, which is 12. A power counts how many times the base appears in a multiplication, and that makes powers grow very fast: `3 ** 10` is already 59049.

**Multiplying and dividing powers of one base.** `3 ** 2 * 3 ** 4` is two 3s multiplied by four more 3s. That is six 3s in all, `3 ** 6`. So multiplying two powers of the same base **adds** the exponents, as Algebra said. Dividing cancels instead. `3 ** 5 / 3 ** 2` is five 3s over two 3s; two of them cancel and three are left, `3 ** 3`. So dividing **subtracts** the exponents. Both rules need the base to be the same on each side: they say nothing about `3 ** 2 * 5 ** 4`.

**Zero and negative exponents.** Write some powers of 3 going down: `3 ** 3` is 27, `3 ** 2` is 9, `3 ** 1` is 3. Each step down takes one from the exponent and divides the answer by 3. Nothing stops the pattern at 1. One more step gives `3 ** 0`, which is 3 divided by 3: 1. Another gives `3 ** -1`, which is 1 divided by 3, a third. Another gives `3 ** -2`, a ninth. So:

- **Any base to the power 0 is 1.**
- **A negative exponent means "one over".** `3 ** -2` is `1 / 3 ** 2`, one ninth. `5 ** -2` is one over 25, which is 0.04.

A negative exponent makes a number **small**. It never makes it negative: `5 ** -2` is 0.04, not -25 and not -10.

```python
print(3**4)
print(3**5 / 3**2)
print(3**0)
print(5**-2)
print(10**-7)
```

```
81
27.0
1
0.04
1e-07
```

Three things to notice in the output. `27.0` has a decimal point because `/` always gives a float, as Arithmetic said. The spaces around `**` are optional and change nothing: `3**4` and `3 ** 4` are the same. And Python prints very small (and very large) floats in a short form: `1e-07` means "1 times 10 to the power -7", which is 0.0000001. You can type numbers that way too: `2.5e-3` is 0.0025.

**Fractional exponents are roots.** The **square root** of 25 is the number that gives 25 when multiplied by itself: 5. In Python it is `25 ** 0.5`. The reason is the adding rule again. `25 ** 0.5 * 25 ** 0.5` must be `25 ** 1`, because 0.5 + 0.5 is 1. So `25 ** 0.5` is a number that times itself makes 25, and that is what a square root is. In the same way `8 ** (1 / 3)` is the **cube root** of 8, the number that makes 8 when three of it are multiplied: 2.

```python
print(25**0.5)
print(8 ** (1 / 3))
```

```
5.0
2.0
```

The answers are floats, because the exponents are. The parentheses in `8 ** (1 / 3)` matter: `**` is done before `/`, so `8 ** 1 / 3` would be 8 divided by 3.

A root undoes a power. Squaring 5 gives 25, and the square root of 25 gives 5 back. It answers the question "which **base**, squared, gives 25?" There is a second way to undo a power, and it is the main idea of this topic.

**A logarithm asks for the exponent.** `2 ** 3` is 8. Three numbers are involved: the base 2, the exponent 3 and the result 8. A power starts from the base and the exponent and finds the result. A root starts from the result and the exponent and finds the base. A **logarithm**, or **log**, starts from the base and the result and finds the **exponent**: "2 to what power is 8?" The answer is 3, and it is written "log base 2 of 8 is 3".

In Python the logarithms live in the `math` module. A *module* is a file of ready-made Python code, and the line `import math` at the top of a program is what makes its functions available. The programs in this topic already have that line; Python Foundations covers importing properly in *Modules and libraries*. `math.log2` is the log base 2 and `math.log10` is the log base 10:

```python
import math

print(math.log2(8))
print(math.log2(64))
print(math.log10(10000))
print(math.log10(500))
```

```
3.0
6.0
4.0
2.6989700043360187
```

Read each one as a question about a power. `math.log2(64)` asks "2 to what power is 64?" Doubling six times from 1 goes 2, 4, 8, 16, 32, 64, so the answer is 6. `math.log10(10000)` asks "10 to what power is 10000?" and the answer, 4, is the number of zeros. A log is not a division: `math.log2(64)` is 6, not 32.

Most numbers are not an exact power of the base, and they still have a log. 500 lies between 100, which is `10 ** 2`, and 1000, which is `10 ** 3`, so its log base 10 lies between 2 and 3: about 2.7. Four more facts are worth knowing:

- **The log of 1 is 0,** in every base, because any base to the power 0 is 1.
- **The log of a number between 0 and 1 is negative.** `math.log10(0.001)` is `-3.0`, because `10 ** -3` is 0.001. Small numbers have negative logs.
- **Zero and negative numbers have no log.** No power of 2 comes out as 0 or as -8, and `math.log2(0)` stops the program with a `ValueError`.
- **A bigger number has a bigger log.** A function like that is called *increasing*. The last part of this lesson depends on it.

A log and a power with the same base undo each other. `math.log2(2 ** 7)` is `7.0`: raise 2 to a power, ask what the power was, and you get it back. Functions that undo each other are called **inverse** functions.

**Three bases, three names.** Any positive number except 1 can be a base, and three are in common use. Base 2 counts doublings, and computing uses it everywhere. Base 10 counts digits, and scales such as loudness and earthquake strength use it. The third base is a number called **e**, about 2.718. It is the base calculus finds easiest to work with, for reasons that belong to calculus, and so it is the one machine learning uses. A log base e is called the **natural log**, and maths books write it `ln`. In Python it is `math.log`, with no number in the name:

```python
import math

print(math.e)
print(math.log(1000))
print(math.log10(1000))
```

```
2.718281828459045
6.907755278982137
3.0
```

The same 1000 has two different logs, because the two functions ask about different bases: e to the power 6.9 is 1000, and so is 10 to the power 3. This is a common bug. A formula that says "log base 10" needs `math.log10`. Writing `math.log` there runs without any error and gives a wrong number, 2.3 times too big.

**The log rules.** There are three, and each is a fact about exponents seen from the other side.

*A product becomes a sum.* 16 is `2 ** 4` and 4 is `2 ** 2`. Multiply them and the exponents add: `2 ** 6`, which is 64. A log is the exponent, so the log of the product is the sum of the two logs. In general, `log(a * b)` is `log(a) + log(b)`.

*A quotient becomes a difference.* Dividing subtracts exponents, so `log(a / b)` is `log(a) - log(b)`. 64 divided by 4 is 16, and 6 - 2 is 4.

*A power becomes a multiple.* `100 ** 3` is `100 * 100 * 100`. By the product rule its log is the log of 100 added three times. So `log(a ** n)` is `n * log(a)`.

```python
import math

print(math.log2(16), math.log2(4))
print(math.log2(16 * 4))
print(math.log2(64 / 4))
print(math.log10(100**3))
```

```
4.0 2.0
6.0
4.0
6.0
```

Two mistakes are common. One is to multiply the logs: 4 times 2 is 8, but the log of 16 times 4 is 6. The logs **add**. The other is to expect a rule for sums. There isn't one: `math.log2(16 + 16)` is the log of 32, which is 5, and nothing simple connects it to 4 and 4. The rules turn multiplying into adding, dividing into subtracting, and raising to a power into multiplying. They work in every base, as long as every log in the line uses the same one.

**Growth by a percentage is repeated multiplication.** Arithmetic showed that adding 20% to a number means multiplying it by `1 + 20 / 100`, which is 1.2. Now let it happen again and again. An app has 400 users and gains 20% every month. Each month's count is the month before times 1.2:

| Month | Growing 20% a month | Adding 80 a month |
| ----- | ------------------- | ----------------- |
| 0     | 400                 | 400               |
| 1     | 480                 | 480               |
| 2     | 576                 | 560               |
| 3     | 691.2               | 640               |
| 4     | 829.44              | 720               |
| 12    | 3566.44             | 1360              |

After `n` months the 400 has been multiplied by 1.2 `n` times. That is a power: `400 * 1.2 ** n`. For any start, any percentage `r` and any number of steps `n`, the amount is `start * (1 + r / 100) ** n`. The number in the parentheses is called the **growth factor**.

The right-hand column is a different kind of growth. It adds 20% of the **starting** 400, which is 80, every month: `400 + 80 * n`. The two columns agree after one month and then part, because the left one takes 20% of a number that keeps getting bigger. Growth by the same **amount** each step is a straight line. Growth by the same **factor** each step is called **exponential growth** (or compound growth, when it is money), and given time it leaves any straight line behind. In code the difference is one character: `1.2 * n` belongs to the straight line, and `1.2 ** n` is the growth.

**Decay is growth with a factor below 1.** A car that loses 15% of its value each year keeps 85% of it, so each year multiplies the value by `1 - 15 / 100`, which is 0.85. An 18000 car is worth `18000 * 0.85 ** 4` after four years, about 9396. Each year's loss is smaller than the last, because it is 15% of a smaller number, and the value never reaches zero.

**Doubling times and half-lives.** Growth is often described by how long one doubling takes. Suppose the data a company stores doubles every 3 years. After 3 years it has doubled once, and after 6 years twice. After `years` years it has doubled `years / 3` times, so it has been multiplied by `2 ** (years / 3)`. The count of doublings doesn't have to be whole. After 4.5 years it is 1.5, and `2 ** 1.5` is about 2.83: more than one doubling and less than two, as it should be. Fractional exponents are what let the formula answer for the times in between.

Halving works the same way with 0.5 as the base. The time one halving takes is called a **half-life**. A 60 gram sample that halves every 8 days has `60 * 0.5 ** (days / 8)` grams left: 30 after 8 days, 15 after 16, and about 10.6 after 20. Keep the parentheses around the division, for the reason given under roots.

**How long until it gets there?** Sometimes the amount is known and the time is wanted. How many months until the app's 400 users have passed 5000? There are two ways to find out.

*Count.* Keep a counter of months, starting at 0. While the amount is still below the target, multiply the amount by the factor and add 1 to the counter. When the loop ends, the counter is the answer. Here the amount after 13 months is about 4280 and after 14 it is about 5136, so the loop stops at 14. A loop like this gives a whole number of steps: the first one at which the target has been reached.

*Use a log.* Going from 400 to 5000 is multiplying by 12.5. So the question is "1.2 to what power is 12.5?", and a question of that shape is a logarithm. Python has no function named for base 1.2, but the power rule gets round that. Take the log of both sides of `1.2 ** n = 12.5`. The left side becomes `n * log(1.2)`, so `n` is `log(12.5) / log(1.2)`:

```python
import math

print(math.log(12.5) / math.log(1.2))
print(math.log(2) / math.log(1.2))
```

```
13.853154222254883
3.8017840169239308
```

The first answer is 13.85 months, so the 14th month is the first one past the target, as the loop said. The second line asks how long the app takes to double. The target is then 2 times the start, whatever the start was, so the time is `math.log(2) / math.log(1 + r / 100)`: about 3.8 months at 20%. Either kind of log works in this formula, as long as the top and the bottom use the same one.

**Why machine learning adds logs.** A *probability* is a number between 0 and 1 that says how likely something is; the next topic covers it. A model that predicts gives a probability to each right answer in its data. Its score for the whole data set is all of those probabilities multiplied together, because the chance of several separate things all happening is the product of their chances. That is where the trouble starts. Every probability is below 1, so each multiplication makes the product smaller. A float has a smallest positive value it can hold, about `5e-324`, and anything smaller is rounded to `0.0`.

Suppose a model gives each of 300 answers a probability of 0.05, and a worse model gives each one 0.04:

```python
import math

print(0.05**100)
print(0.05**300)
print(0.04**300)
print(300 * math.log(0.05))
print(300 * math.log(0.04))
```

```
7.888609052210162e-131
0.0
0.0
-898.7196820661973
-965.6627474604602
```

A hundred answers still fit. Three hundred don't: both products come out as `0.0`, and nothing is left to tell the two models apart. The last two lines use the logs. By the product rule, the log of a product is the sum of the logs, so instead of multiplying 300 probabilities the program adds 300 logs (here they are all equal, so it is 300 times one log). Each log is negative, because each probability is below 1, and the total is an ordinary negative number that a float holds easily.

Nothing is lost by doing this. A log is increasing, so the larger product has the larger log. -898.7 is larger than -965.7, so the first model is the better one, which is what 0.05 against 0.04 should give. Whenever a machine-learning text says "log-probability", "log-likelihood" or "cross-entropy", this is what is going on: logs of probabilities, added.

<Recap>

- **Powers:** `2 ** 10` is 1024. **Negative exponents** mean "one over": `2 ** -2` is `0.25`. **Fractional exponents** are roots: `16 ** 0.5` is `4.0`, the square root.
- **A logarithm undoes a power.** `math.log2(1024)` is `10.0`: "2 to what power is 1024?" `math.log10(100)` is `2.0`. `math.log(x)` with no base is the natural log, base `e` (about 2.718), which calculus and machine learning prefer.
- **The rules,** each one a fact about exponents in disguise:
  - product → sum: `log(a * b)` is `log(a) + log(b)`;
  - quotient → difference: `log(a / b)` is `log(a) - log(b)`;
  - power → multiple: `log(a ** n)` is `n * log(a)`.
- **Growth is a power.** Something that grows by `r` percent each step is multiplied by `(1 + r / 100)` each step: after `n` steps, `start * (1 + r / 100) ** n`. **Decay** is the same with a factor below 1: a dose that halves every 6 hours is `start * 0.5 ** (hours / 6)`.
- **How long until it doubles?** Either loop, multiplying until the amount passes double, or use a log: `math.log(2) / math.log(1 + r / 100)` years.
- **Why ML adds logs.** A model's confidence in a whole data set is many probabilities multiplied together, each between 0 and 1. The product is so small that a float rounds it to `0.0`. Add the logs instead: an ordinary negative number, with the same ranking, and the product rule says it's the same information. "Log-likelihood" and "cross-entropy" are this trick with names.

</Recap>
