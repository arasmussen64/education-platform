<Intro>

"Cores, memory and noisy neighbours" priced machines by the hour. Put **Windows Server** on one (Microsoft's operating system for servers, which many companies run beside Linux), add **SQL Server** (Microsoft's database), and the software can cost more than the machine. This topic is about that part of the bill: how Microsoft's server software is counted (in cores, with minimums), what the clouds charge when they rent it to you by the hour, when a company may bring licences it already owns, and when renting a whole server, a dedicated host, is the cheaper way. The rules are Microsoft's and they change, so the topic teaches them **as Microsoft's Product Terms stood in November 2026**, each with where it is written, and teaches where to look the rest up. Several questions ask you to work out a number; use a calculator whenever you like, because the skill is setting up the sum.

**The licence can cost more than the machine.** Here is one Azure VM, `Standard_D4s_v5` (4 vCPUs, 16 GiB of memory; a GiB, or gibibyte, is 1,024 × 1,024 × 1,024 bytes, about 7% more than the GB that SQL Server's limits below are given in) in East US, for a 730-hour month, at the pay-as-you-go prices read on 2026-11-11. The hardware is the same in every row:

| What runs on it | Per hour | Per month | The machine's share |
| --- | --- | --- | --- |
| Linux | $0.192 | $140.16 | 100% |
| Windows Server | $0.376 | $274.48 | 51% |
| Windows Server and SQL Server Standard | $0.776 | $566.48 | 25% |
| Windows Server and SQL Server Enterprise | $1.876 | $1,369.48 | 10% |

Everything after the first row is rent for software, and it is charged per vCPU: $0.046 a vCPU-hour for Windows Server, $0.10 for SQL Server Standard and $0.375 for Enterprise. That is why this topic keeps counting cores.

**What a licence is.** A **licence** is the right to use a piece of software, on terms the maker sets. A **perpetual** licence is bought once and kept; a **subscription** licence is rented by the year and ends when you stop paying. Server software is sold as **core licences**, one for each processor core (a physical core, or a vCPU when it is licensed in a VM), bought in packs. Each product comes in **editions**: Windows Server **Standard** and **Datacenter** differ in how many VMs they cover; SQL Server, a database server (a program that stores an application's data and answers its questions about it, and usually the most expensive software on the machine), comes as **Enterprise**, **Standard**, two free **Developer** editions and the free, small **Express**. When a company runs its own server it also needs a **CAL** (client access licence) for each person or device that uses it; the clouds' rented Windows needs none (AWS and Azure both say so). Companies buy Microsoft licences in bulk through **volume licensing**, often an **Enterprise Agreement**, a contract of several years. **Software Assurance** (SA) is a yearly add-on to licences bought that way: it brings new versions as they come out and, what matters here, the right to use the licences in more places. None of Microsoft's price pages gives a price for it; a reseller quotes it. And every rule in this topic comes from Microsoft's **Product Terms**, the published licence terms for each product, which are the final word: Microsoft Learn's own page on the subject says the Product Terms "take precedent over this article". They call each running copy of an operating system an **OSE** (operating system environment); in this topic that is a VM, or a physical server's own operating system.

**Counting Windows Server cores.** On a server you own and license yourself, every physical core needs a core licence, with two minimums: at least **8 per processor** and **16 per server**. A server with one 4-core processor needs 16; one with two 20-core processors needs 40. **Standard** then lets you run **2 VMs** on that server, and you may license every core again for 2 more ("stacking"); **Datacenter** lets you run **any number**. Microsoft's list prices for Windows Server 2025 (read 2026-11-11) were $1,176 for 16 core licences of Standard and $6,771 for Datacenter, so on a server with many VMs Datacenter becomes the cheaper edition; one of the questions works out from how many. Licensed **by VM** instead, which needs Software Assurance or a subscription, a VM needs one core licence per vCPU and **at least 8**: a 4-vCPU VM takes 8, a 12-vCPU VM takes 12. That per-VM rule is the one Azure Hybrid Benefit uses, below. A **processor licence**, an older kind still in some companies' contracts, counts as 16 core licences.

**Licence included.** Every cloud will rent you Windows Server by the hour inside the VM's price, and then you own nothing and count nothing: AWS calls it **licence included**, Azure **pay-as-you-go**, Google Cloud an **on-demand licence**. On the **general-purpose** sizes (the everyday ones, such as Azure's D series and AWS's m) and the **memory-optimised** ones (twice the memory for each vCPU, such as Azure's E series and AWS's r) it cost **$0.046 a vCPU-hour** on all three clouds when this topic was written (AWS publishes the rate on its "Optimize CPUs" page; on Azure it is the Windows price minus the Linux price; Google adds it as a "premium image" line on the bill), which is about $34 a vCPU a month. AWS's and Azure's smallest burstable sizes are priced apart and pay much less: an Azure `Standard_B2ls_v2` paid $0.0092 an hour more for Windows, not 2 × $0.046 (on Google Cloud only its two oldest small types, `f1-micro` and `g1-small`, pay less). So $0.046 is a rule of thumb for an estimate before you open a calculator, never a price to put in a budget. SQL Server licence included is charged the same way, per vCPU, for at least 4 vCPUs, and its rates differ a little by cloud: Standard was $0.10 a vCPU-hour on Azure and $0.12 on AWS and Google Cloud, Enterprise $0.375 on Azure and AWS and $0.399 on Google Cloud.

**Bringing your own licences to Azure: Azure Hybrid Benefit.** **Bring your own licence** (BYOL) means running licences you already own on the cloud's machines, and paying the cloud only for the machine. On Azure that is **Azure Hybrid Benefit**, and it needs Windows Server core licences **with active Software Assurance** (or subscription licences). Turned on, a Windows VM costs the Linux price. You set aside core licences by the per-VM rule, **at least 8 a VM**. While Software Assurance lasts the benefit lasts; let it lapse, and the benefit must be turned off (a setting on the VM, with no restart) and the VMs pay the Windows price again. Moving takes time, so Microsoft lets the same licences cover the old servers and the Azure VMs for a while: **180 days** for Standard, and for Datacenter licensed by VM, **indefinitely**. The main resource below is Microsoft's own page on all of this.

**Bringing your own licences to AWS and Google Cloud.** Microsoft's rules are stricter for the other big clouds. From **1 October 2019**, licences bought without Software Assurance may no longer be deployed on the dedicated hosting of a **Listed Provider** (licences bought before that date keep the right they had), and Microsoft's list of them, which it says "is subject to change", names Alibaba, Amazon, Google and Microsoft itself. That leaves two doors, and which one a licence can use depends on the product:

- **License Mobility** is a Software Assurance benefit that lets a licence run on an authorised cloud partner's shared servers. **SQL Server has it; Windows Server doesn't**, "even if the licenses have SA", as AWS's guidance puts it. So SQL Server with Software Assurance moves to ordinary AWS instances and Google Cloud VMs, counted as on any VM (one licence a vCPU, at least 4), and Windows Server doesn't move to them at all.
- **Dedicated hardware** is the door for products without License Mobility, and for licences without Software Assurance: an AWS **Dedicated Host** or a Google Cloud **sole-tenant node** (a server of your own, as "Hypervisors" showed). It takes only perpetual licences bought **before 1 October 2019** (or within an Enterprise Agreement that began before then), for a version released before then, which for Windows Server means **2019 or older**. On AWS they must cover **all the host's physical cores**, not the VMs' vCPUs; Datacenter on every core then runs as many instances as fit, and each full set of Standard runs two. Microsoft is on its own list, so Azure's dedicated hosts take the same old licences on the same terms, every physical core licensed (the FAQ of Azure's dedicated-host pricing page, a resource below, says so).

So **Windows Server 2022 and 2025 are licence included on AWS and Google Cloud, always**: AWS's FAQ says plainly that neither is "eligible for BYOL". The three questions to ask of any licence, then, are which product, whether its Software Assurance is active, and which cloud:

| As the rules stood in November 2026 | Azure | AWS | Google Cloud |
| --- | --- | --- | --- |
| Windows Server, active Software Assurance | Yes: Azure Hybrid Benefit, at the Linux price, at least 8 core licences a VM | Not on shared instances (no License Mobility) | Not on shared VMs (no License Mobility) |
| Windows Server bought before 1 October 2019, version 2019 or older, with or without Software Assurance | With active Software Assurance, as above; without it, on a dedicated host, every physical core licensed | On Dedicated Hosts, every physical core licensed | On sole-tenant nodes |
| Windows Server 2022 or 2025, no Software Assurance | No | Licence included only | Licence included only |
| SQL Server, active Software Assurance | Yes: Azure Hybrid Benefit | Yes, on shared instances: License Mobility, at least 4 a VM | Yes, on ordinary VMs: License Mobility |
| SQL Server, no Software Assurance | Only on a dedicated host, bought before 1 October 2019, for a version released before then | Only on Dedicated Hosts, bought before 1 October 2019, version 2017 or older | Only on sole-tenant nodes under the 2019 conditions; check Google's licensing page first |

Licences without Software Assurance, then, are treated alike on all three clouds: old ones on dedicated hardware only, newer ones nowhere. Azure is kinder in one way: Azure Hybrid Benefit, a right Microsoft gives for its own cloud, takes licences with Software Assurance onto shared hardware, Windows Server included. Google adds one detail: a licence brought to a region can't move to another region for 90 days.

**SQL Server: the cheapest core is the one you don't license.** SQL Server is licensed per core in packs of 2, at least 4 per processor on your own server and **at least 4 per VM** when licensed by VM (with Software Assurance or a subscription). The minimum shows in every price list: Azure's smallest SQL Server meter is named "1-4 vCPU VM", so a 2-vCPU VM paid the same $0.40 an hour for SQL Server Standard as a 4-vCPU one, and Google's page says "Instances with fewer than 4 vCPUs will be charged for 4 vCPUs". The licence is several times the machine (the table at the top: Enterprise was $1.50 an hour of that VM's $1.876), so the way to a smaller bill is fewer licensed cores:

- **Size by memory.** A database is usually sized by how much data it keeps in memory, and a memory-optimised size (Azure's E series, AWS's r) gives the same memory with half the vCPUs of a general-purpose one.
- **Switch vCPUs off.** AWS lets a licence-included instance run with only some of its vCPUs on, keeping all its memory, and charges the licences only on those ("Optimize CPUs").
- **Pick the edition.** In SQL Server 2025, **Standard** uses at most 32 cores (24 in SQL Server 2022 and earlier) and 256 GB of memory for its cache; **Enterprise** has no limits but the machine's; the two **Developer** editions are free and complete but only for development and test, never production; **Express** is free for production too, but uses at most 4 cores and holds at most 50 GB a database (10 GB in SQL Server 2022 and earlier). The Web edition, which AWS and Google Cloud still rent by the hour, is gone from SQL Server 2025. Always name the version when you quote a limit.

On Azure, Hybrid Benefit for SQL Server has exchange rates of its own: one Enterprise core licence covers 4 vCPUs of a VM running Standard, and a VM still takes at least 4 core licences.

**Dedicated hosts: a whole server, full or empty.** A dedicated host (AWS and Azure) or sole-tenant node (Google Cloud) is billed whole, by the hour, however many VMs it runs; Azure's page says it is charged "per dedicated host, regardless how many VMs are deployed". In the prices read for this topic a full host cost about **10% more** than the same capacity bought as shared VMs, on all three clouds. Only Google states it as a rule ("a sole-tenancy premium, which is 10%"); for AWS and Azure it is what the prices worked out to on the day, so work it out again. A host is the cheaper choice in two cases. Either the licences you own are only allowed there (old licences without Software Assurance, on any of the three; old Windows Server on AWS or Google Cloud, with Software Assurance or without), or licences are counted on its **physical cores** and you run enough VMs on it. Here is an Azure Dasv5-Type1 host (64 physical cores, 112 vCPUs, at most 28 `Standard_D4as_v5`, $5.298 an hour) filling up with 4-vCPU Windows VMs:

| VMs on the host | Core licences, licensing each VM (8 each) | Core licences, licensing the host (Datacenter) |
| --- | --- | --- |
| 4 | 32 | 64 |
| 8 | 64 | 64 |
| 16 | 128 | 64 |
| 28 (full) | 224 | 64 |

Below 8 VMs, licensing the host takes more licences and wastes most of the server; full, it takes 160 fewer, for a host that costs a tenth more than 28 VMs on shared hardware ($5.298 against 28 × $0.172 = $4.816 an hour). Now say the company already owns those 64 Datacenter core licences, with Software Assurance, so its Windows VMs on the host cost nothing but the host. Against Windows licence included on shared hardware, the host is then a **break-even** sum: the host's price over one VM's licence-included price, and the next whole number up. A `Standard_D4as_v5` with Windows was $0.356 an hour, and $5.298 ÷ $0.356 = 14.9, so 14 VMs ($4.98 an hour) are still cheaper and from 15 the host wins. So the answer to "is a dedicated host cheaper?" always starts with "how full will it be, and how are the licences counted?" One more thing to read in the provider's table: how many VMs of your size fit, which is not always the vCPUs divided by the size.

**What holds and what moves.** Keep the two apart in everything you write:

| Rules, as the Product Terms stand in November 2026 | Look up on the day, and where |
| --- | --- |
| Server software is counted in cores, with minimums: Windows Server 8 a processor and 16 a server on your own hardware, 8 a VM by VM; SQL Server 4 a processor or a VM | Every price, the $0.046 included: each cloud's price page, copied into a dated table |
| Standard covers 2 VMs per fully licensed server; Datacenter any number | Which versions may be brought to AWS and Google Cloud, and the 2019 conditions: the Product Terms, and each cloud's licensing FAQ |
| Software Assurance is what lets a licence move: by VM, to Azure, through License Mobility | Who the Listed Providers are: Microsoft's list, "subject to change" |
| SQL Server has License Mobility; Windows Server doesn't | SQL Server's editions and their limits, by version: Microsoft Learn's editions page |
| Licence included is paid per vCPU-hour and needs no CALs | Azure Hybrid Benefit's allowances and exchange rates: the Product Terms' "Microsoft Azure" entry |
| A dedicated host is billed whole, full or empty | The host premium, and how many VMs of a size a host holds: the provider's host pricing and sizes pages |

Product names move too: Azure Stack HCI (Microsoft's software for running Azure's services on a company's own servers, a tab of the main resource) is now Azure Local, and Azure AD (Microsoft's cloud directory of a company's users) is now Entra ID. **Try the look-up once now**, before the questions: open Azure's "Windows Virtual Machines Pricing" page (the last resource below), choose the region East US, find `D4s v5`, and compare its price with the $0.376 in the table at the top, read on 2026-11-11. If it differs, the table is out of date and the method isn't.

**The method, in five steps.** The worked example follows it step by step. (1) List the servers: cores, operating system, SQL Server edition, and for each licence whether its Software Assurance is active and when it was bought. (2) Count the core licences with the minimums. (3) Ask the three questions (product, Software Assurance, cloud) to find each server's allowed options. (4) Price each allowed option for a 730-hour month. (5) Compare, and write down the date of the prices and everything you assumed.

**Minimums in `awk`.** The labs do step 2 and step 4 over a list of servers in a CSV file, with `awk` as Shell essentials taught it, and one new habit: a minimum written as rules that run in order on each line. `{n = $2} n < 8 {n = 8} {total += n}` sets `n` to the vCPUs, raises it to 8 when it is lower, and adds it up; `END {printf "%.2f\n", total * 730}` prints a month's money to the cent (`printf` prints its arguments in the layout it is given; `%.2f` is a number with two decimals and `\n` ends the line). `tail -n +2 FILE |` in front drops the heading line, and `awk -v rate=0.10` hands a number into the program by name.

<Recap>

- **Licences are counted in cores, with minimums.** Windows Server on your own server: every physical core, at least 8 a processor and 16 a server; Standard covers 2 VMs per full set (stack sets for more), Datacenter any number. By VM (Azure Hybrid Benefit): one a vCPU, at least 8 a VM. SQL Server: one a core or vCPU, at least 4 a processor or VM, in packs of 2.
- **Licence included** is paid per vCPU-hour: Windows Server about $0.046 on all three clouds in November 2026 (less on AWS's and Azure's smallest burstable sizes), SQL Server Standard $0.10 to $0.12 and Enterprise $0.375 to $0.399, for at least 4 vCPUs. No CALs. The licence is often more than the machine.
- **Can we bring them?** Product, Software Assurance, cloud. Azure: both products with active Software Assurance, through Azure Hybrid Benefit, at the Linux price; Standard may overlap with the old servers for 180 days, Datacenter by VM indefinitely. AWS and Google Cloud, two of Microsoft's Listed Providers: SQL Server with Software Assurance on shared VMs through License Mobility; Windows Server only as licences bought before 1 October 2019 for 2019 or older, on Dedicated Hosts (every physical core licensed) or sole-tenant nodes. Windows Server 2022 and 2025 are licence included there. Licences without Software Assurance: on any of the three, only old ones, only on dedicated hardware.
- **SQL Server:** the licence is most of the bill. Size by memory on a memory-optimised size, switch unneeded vCPUs off, never go under 4; Standard to 32 cores (2025), Developer free for test only, Express free to 4 cores and 50 GB.
- **Dedicated host:** a whole server, billed full or empty, about 10% over the same capacity shared (in the prices read). It pays when licences are only allowed there, or when licensing its physical cores replaces licensing many VMs. Break-even: the host's price over one licence-included VM's, then the next whole number.
- **Look it up:** the Product Terms settle a rule; each cloud's licensing pages say how it applies there; every price goes in a dated table. Name the version with every limit and the date with every price.

</Recap>
