<Intro>

Everything in this module meets here. A network is a chain: multiply the inputs by a matrix of weights, add a **bias** (one number per unit, added to its score so the unit can switch on even when the inputs are zero), bend with ReLU, multiply again, squash with a sigmoid, measure the cross-entropy. The forward pass runs that chain and keeps every intermediate value. The backward pass is the chain rule from the last topic run from the loss inward, with matrices where the numbers were, and the loss topic's `p - y` as its first factor. Then gradient descent trains it. This topic builds a network of two inputs, four **hidden** units (the middle layer, so called because its values are neither the inputs you give nor the output you read) and one output, checks every gradient numerically, and trains it to learn XOR (exclusive or: the answer is 1 when exactly one of two inputs is 1), the small problem no single straight line can solve.

The main resource is **3Blue1Brown's _Neural networks_, chapters 3 and 4**, what backpropagation is really doing and backpropagation calculus; about 25 minutes, and chapter 4 is this topic's backward pass drawn as a tree. The link here is chapter 3; chapter 4 is first under **More resources**, below the lesson. Michael Nielsen's chapter 2 has the same derivation in text, with the four equations named. Watch for:

- **The sensitivity picture:** how much the loss cares about each weight, found by walking back from the output.
- **Why `h` appears in the gradient of `W2`:** a weight's gradient is its input times the gradient at its output.
- **The mask:** a ReLU that's off passes no gradient back.

</Intro>

<Recap>

- **The network.** For inputs `X` (one row per example, two columns), `z1 = X @ W1 + b1` (four hidden scores per example), `h = np.maximum(z1, 0.0)` (the bend), `z2 = h @ W2 + b2` (one output score), `p = sigmoid(z2)`. `W1` is 2 by 4, `b1` has 4 entries, `W2` has 4, `b2` is one number. The loss is the mean cross-entropy of `p` against `y`.
- **The forward pass** computes and **keeps** `z1`, `h` and `p`, because the backward pass evaluates each local derivative at that link's input.
- **The backward pass**, from the loss inward, one line per link:
  - `dz2 = (p - y) / n`: the gradient of the mean cross-entropy with respect to the output score (the loss topic's `p - y`).
  - `dW2 = h.T @ dz2` and `db2 = dz2.sum()`: `z2 = h @ W2 + b2`, so a weight's gradient is its input `h` times the gradient at its output, summed over examples.
  - `dh = np.outer(dz2, W2)`: the same product the other way, each example's `dz2` spread along `W2`.
  - `dz1 = dh * (z1 > 0)`: ReLU's derivative is the **mask**, 1 where the unit was on, 0 where it was off.
  - `dW1 = X.T @ dz1` and `db1 = dz1.sum(axis=0)`: `z1 = X @ W1 + b1`, so `X` plays the part `h` played a layer later.
- **Every gradient has the shape of its parameter:** `dW1` is 2 by 4 like `W1`, `db1` has 4 entries like `b1`. A shape error in the backward pass is a line with the wrong product or a missing transpose.
- **The gradient check.** For each weight: nudge it by a small `eps = 1e-6` up and down, run the forward pass and the loss both times, and divide the difference by `2 * eps`; compare with your gradient. `np.allclose(..., atol=1e-6)` for every parameter before any training. If `W2` passes and `W1` fails, the bug is between them: `dh`, the mask or `dW1`. One honest false alarm: a hidden unit sitting **exactly** at the bend (`z1 == 0` for some example) makes the two nudges land on different sides of the corner. The mask `z1 > 0` counts the unit as off, so your gradient gets nothing from that example, while the nudge upwards switches the unit on and the nudge downwards doesn't, so the numeric slope reports half of the on-side slope. The two disagree although neither line is wrong; starting weights without exact zeros avoid it.
- **Training** is the descent loop from three topics ago: forward, loss, backward, `W = W - rate * dW` for each parameter. From the worked example's starting weights at rate 0.5, the loss on XOR falls from 0.732 to 0.001 in a thousand steps and all four predictions are right.
- **Dead units.** A hidden unit whose `z1` is negative for every example has a mask of zeros, gets no gradient, and never changes. Big learning rates and bad starts kill units; it's a reason starting weights are small and random in practice.
- **In machine learning:** this is what `loss.backward()` does in PyTorch, for every layer type, with the same bookkeeping; the next topic improves the update rule, and the checkpoint trains this network with it.

</Recap>
