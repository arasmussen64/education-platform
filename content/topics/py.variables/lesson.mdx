<Intro>

A **variable** is a name for a value, so your program can keep the value and use it later. In this part of the lecture, watch for:

- **The `=` sign**: David says it isn't "equals". It means "assign", working from right to left.
- **Choosing a name**: why `name` is a better name than `x`.
- **A classic mistake**: what happens when the variable's name ends up inside the quotes.

David gets his value from `input()`, which asks the user to type something. That comes properly in topic 5; here, just watch what happens to the value once it has a name.

**One correction to the video's picture.** David calls a variable a *container* that the value is copied into. A more accurate picture is a **name tag**: the name points at a value, and `=` moves the tag. For text and numbers both pictures give the same answers. When you reach lists (Module 5), only the name-tag picture keeps working, so this lesson uses it from the start.

</Intro>

<Recap>

- `name = value` makes the **name refer to the value**. Read `=` as "now refers to", not "equals". Python works out the right side first, then points the name on the left at the result.
- Using a name gives you its value: `print(city)` shows what `city` refers to. With quotes, `print("city")` shows the word `city`. Quotes mean text; no quotes means a name.
- `=` can point a name at a **new value** at any time. The old value is simply no longer named by it.
- `b = a` points `b` at **whatever `a` refers to at that moment**. It doesn't tie the two names together: if `a` later refers to something else, `b` doesn't follow.
- **Trace** code one line at a time, from the top, writing down what each name refers to after each line. It's the surest way to predict what a program does.
- To **swap** two values, keep one safe under a spare name first: `temp = x`, then `x = y`, then `y = temp`. Writing just `x = y` then `y = x` loses `x`'s original value. Both names end up with `y`'s value.
- Using a name that was never given a value, or misspelling one, is a `NameError`.

</Recap>
